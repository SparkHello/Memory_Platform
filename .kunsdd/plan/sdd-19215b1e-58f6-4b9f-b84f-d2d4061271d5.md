
# 电脑端 Memory API — Phase 3 & Phase 4 实施计划

## Phase 4: 记忆命中可见性（非流式）

### 4.1 修改 `app/openai_compat/chat.py`

在 `create_chat_completion()` 函数中，reference `memories` 变量已在函数作用域内可用（第 99 行 `memories = await search_service.search(...)`）。在返回 `client_response` 之前插入记忆命中块。

#### 4.1a 添加记忆命中格式化函数

在 `chat.py` 中新增：

```python
def _format_memory_hit_block(
    query: str,
    memories: list[MemoryRecord],
    tool_name: str = "search_memory",
) -> str:
    """Build an inline memory hit block for non-streaming responses."""
    if not memories:
        return ""
    lines = [
        "【记忆命中】",
        f'🔍 {tool_name}("{query}") → {len(memories)} 条',
    ]
    for i, m in enumerate(memories, 1):
        score = getattr(m, "score", None)
        score_str = f" (相关度 {score:.2f})" if score is not None else ""
        content_preview = m.content[:80].replace("\n", " ")
        lines.append(f"{i}. {content_preview}{score_str}")
    lines.append("---")
    return "\n".join(lines)
```

#### 4.1b 在返回前注入命中块

在 `create_chat_completion()` 的 `return client_response` 前（约第 138 行），添加：

```python
    # 注入记忆命中块（非流式）
    if memories and latest_user_message:
        hit_block = _format_memory_hit_block(latest_user_message.content, memories)
        if hit_block:
            choices = client_response.get("choices", [])
            if choices and isinstance(choices[0], dict):
                msg = choices[0].get("message", {})
                if isinstance(msg, dict):
                    original = msg.get("content", "") or ""
                    msg["content"] = hit_block + "\n" + original
```

## 风险与注意事项

1. **MCP 客户端兼容性**：移除 13 个工具后，使用旧版 instructions 的 MCP 客户端可能尝试调用不存在的工具。由于 MCP SDK 的工具列表是动态的，客户端会收到新的 4 个工具列表，但需要确保 instructions 中的「引导到 Web UI」信息清晰。

2. **REST 端点保留**：13 个工具对应的 REST 端点（如 `POST /memories/merge`、`GET /memories/export` 等）**全部保留**，不受 MCP 精简影响。删除的只是 MCP 工具注册和函数，不是 REST 端点实现。

3. **记忆命中块格式**：命中块拼接在前端 assistant content 前，下游客户端需要能处理这个额外前缀。格式是纯文本，不会破坏 JSON 结构。

4. **Phase 4 仅影响网关模式**：`POST /memories/context` 的电脑端 API 不受影响，调用方自行决定展示方式。

5. **测试回归**：删除 18 个 MCP 测试后，`test_rest_endpoints_still_work` 确保 REST 端点不受影响。

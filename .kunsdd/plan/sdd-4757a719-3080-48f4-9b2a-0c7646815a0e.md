# Web Console 首次使用体验优化 — 实施计划

## 概要

把新用户「打开控制台 → 能聊天」的链路收敛为一条不回头的主线。六项工作按价值/成本排序：评测页假错误修复、全局横幅收敛、admin key 会话保持、简洁模式术语隐藏、空态下一步引导、一次性登录链接（最大项，含后端 + CLI + 双安装器）。

**工作树现状提醒**：`services/memory-gateway/ui` 有未提交改动（App.tsx、AppShell.tsx、ErrorBoundary 等韧性工作），实施前 `git status --short` 确认并保留这些改动；Docker 镜像内的 UI 构建落后于工作树（评测页 404 静默在工作树已存在但镜像里没有），所有验证必须基于新构建。

## 关键现状（已核实）

- `ui/src/App.tsx:249-289` `pingService` 拉取 `api.providersStatus()` 得到 `setupStatus`（`ProvidersStatus["setup"]`：`state / service_ready / chat_ready / next_action / missing_chat_routes`），已作为共享「配置进度」数据源传给 Dashboard。
- 全局横幅 = `ui/src/layout/AppShell.tsx:245-262` 的 `status-pill` 按钮，每页顶栏都渲染，不可关闭。
- admin key 不落地：从 ProvidersPage 逐层 prop 下传（`AddChannelModelPanel.tsx:16`、`NewChannelWizard.tsx:210`），每次调用以 `X-Model-Gateway-Admin-Key` 头发送（`api.ts:219` 等 13 处）。
- 评测页：`EvaluationPage.tsx:113` 已把 workbench 404 吞掉返回 null，但请求本身仍发出（网络面板 404 噪音）；`app/memory/evaluation.py` 有 `eval_workspace_paths / require_eval_workspace` 可低成本判断快照是否存在。
- 认证：`app/auth/middleware.py` `EarlyAuthMiddleware` 仅认 `Authorization: Bearer`，按路径定 role；`/ui` 静态资源免鉴权。`memgw open`（`app/cli.py:990-997`）只打开裸 URL。token 哈希存 AUTH DB（`app/auth/tokens.py`、`app/api/auth_tokens.py`）。
- Docker 安装器 `deploy/install.sh` 与 `install.ps1` 双实现，`tests/test_installer_parity.py` 钉住共享常量——改一边必须改另一边。

## 范围外（本期明确不做）

- 简洁/专家两套导航分组的统一重构（P2 背景提及，但目标与验收未要求；单独立项）。
- 聊天客户端（Chatbox 等）侧的任何改动。
- Model Gateway 自身 UI/接口改动（仅消费既有 `providersStatus`）。

## 实施步骤（按 ICE 排序）

### 1. 评测页：未初始化 ≠ 错误，且无 4xx 噪音

- [ ] 后端 `app/memory/evaluation.py` + `app/api/memories/evaluation.py`：在 diagnosis 响应中增加 `snapshot_initialized: bool`（用 `eval_workspace_paths` 检查快照文件是否存在，不抛异常）；保持 workbench 404 行为不变作为兜底。
- [ ] 前端 `ui/src/pages/memory/EvaluationPage.tsx`：`load()` 先取 diagnosis，仅当 `snapshot_initialized` 为真时才并发请求 workbench；未初始化直接渲染现有空态（`label="尚未初始化召回评测快照"` + 「初始化快照」主按钮，行 466-468 已有），不出现错误条。保留既有 404 静默逻辑作为防御。
- [ ] 「初始化快照」成功后复用现有 `load()` 刷新，确认初始化→标注流程无回归。

### 2. 全局状态横幅：相关页才出现、可关闭、跨页保持

- [ ] `ui/src/layout/AppShell.tsx` + `App.tsx`：warning 类横幅（「服务在线 · 待配置模型」「模型配置需处理」）只在 dashboard / providers / settings / developer 四个页面渲染；bad（服务异常）横幅不受限、不可关闭。

### 3. admin key 会话内保持（目标 1 主线）

- [ ] ProvidersPage、NewChannelWizard、AddChannelModelPanel 改从该模块读取替代纯 prop 起始值（prop 链路保留给显式输入）。

### 4. 简洁模式隐藏内部术语（目标 5）

- [ ] `ui/src/pages/DashboardPage.tsx:1128-1132`：`setup.missing_chat_routes` 的原始 ID 列表（`memory.chat` 等）仅在专家模式渲染；简洁模式显示「N 项用途尚未就绪」。

### 5. 空库空态的「下一步」引导（目标 3）

- [ ] App.tsx 把 `setupStatus` 透传给这 5 个页面（Dashboard 已有先例）。

### 6. 一次性登录链接（目标 2，最大项）

- [ ] 后端 `app/auth/tokens.py` + `app/api/auth_tokens.py`：新增 `POST /auth/console-login-code`（需 console role Bearer，即 install/CLI 用 gateway token 调）→ 生成一次性 code：AUTH DB 新表/新列存哈希、5 分钟 TTL、单次使用；新增 `POST /auth/console-login-exchange`：`{code}` → 返回 console token 明文一次。交换端点在 `EarlyAuthMiddleware` 中免 Bearer，但**仅允许 loopback 客户端 IP**（复用 `app/config.py` 已有的 ipaddress 逻辑）并加既有速率限制；code 无效/过期/复用一律 401，不区分原因。
- [ ] UI `ui/src/App.tsx` 启动时检查 `location.hash` 中 `#login=<code>`：存在则调 exchange → `saveSettings` 写入 → 立即 `history.replaceState` 抹掉 hash → 触发 `pingService`；失败则落入现有首启填 key 页并提示「登录链接已失效，请重新运行 memgw open」。
- [ ] CLI `app/cli.py::_open_console`：从本地凭据目录读 console token（0600 文件，同用户可读），调 mint 端点拿 code，打开 `http://localhost:{port}/ui/#login=<code>`；mint 失败时回退为裸 URL 并打印一行提示（不打印 token/code）。
- [ ] Docker 安装器：`deploy/install.sh` 与 `deploy/install.ps1` 在首次启动成功后，用 `credentials/gateway.txt` 调 mint 端点并打印一次性登录 URL（两实现同步改， parity 测试覆盖新增输出格式）；URL 只打印到终端，不写日志文件。
- [ ] 手动粘贴 gateway.txt 的首启流程原样保留作为兜底。

## Pre-mortem 风险评估

**Tigers（真实风险，需行动）**

- T1【Launch-Blocking】一次性 code 交换端点扩大本地攻击面：本机任意进程拿到 code 即可换 token。缓解：code 单次使用 + 5 分钟 TTL + 仅 loopback + 速率限制 + mint 需 console token + 不明文存储。负责人：后端实施者；决策时点：步骤 6 开工当天评审端点设计后再写码。
- T2【Launch-Blocking】admin key 进 sessionStorage 比现状（仅页面 state）扩大了 XSS 读取窗口。缓解：仅验证成功后写入、提供「忘记」按钮、永不进 localStorage、在 PR 描述中按服务 AGENTS.md 安全清单过一遍；威胁模型限定为本机 Console 可接受。负责人：前端实施者；决策时点：步骤 3 PR 评审。
- T3【Fast-Follow】Docker 镜像 UI 陈旧掩盖工作树修复（本次实测即踩到）：验收前必须重建镜像复测，并把「镜像 UI 版本」写进验收记录。30 天内在安装器加 UI 构建版本提示。
- T4【Track】一次性链接 URL（含已用 code）留在浏览器历史：code 已失效，风险低；观察即可。

**Paper Tigers（他人可能担心，记录以对齐）**

- 「URL 带登录信息违反安全模型」：hash 不发送到服务器、不进服务端日志，且传输的是一次性 code 而非 token 本体，用后即成死串。
- 「sessionStorage 等于持久化密钥」：tab 级生命周期，关闭即失效，正是验收要求的上限。

**Elephants（需先查清再承诺）**

- 若用户把服务暴露到非 loopback（公网/局域网），exchange 端点行为：计划已要求仅 loopback，但需在 T1 评审时确认默认绑定与 `ALLOW_PRIVATE_HTTP` 类配置的交互，必要时加配置开关默认关。

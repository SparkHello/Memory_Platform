# Web Console 视觉观感、文案精简与易用性

## 背景

Console 面向的用户不都懂技术，界面应默认直观、藏起技术细节（细节放文档，需要可查），不能"太乱"。现状：已有设计 token、深/浅双主题（`ui/src/styles/tokens.css`）和简洁/专家双模式（`AppShell.tsx`），但视觉、文案与易用性仍粗糙。来源为 2026-08-12 综合评审 UI/UX 节（`docs/reviews/JJC-20260812-003-comprehensive-review.md`）与代码核查：

**视觉观感**

- 深色「暮色琥珀」主题用大量 `rgba(255,255,255,0.x)` 半透明文字叠在玻璃材质上，对比度未经验证；浅色主题有"≥6.5:1 脚本验证"记录，深色没有等价验证。
- 危险等级 warning/danger 的视觉与确认弹窗使用不一致；低风险操作（如编辑记忆）每次弹确认，形成视觉噪音。
- 移动端 780px 断点下 pages.css 约 35 行 sidebar 样式被 morning-crystal.css 覆盖成死代码；首配阶段底栏缺「模型」入口。
- 少量绕过 token 的硬编码色值（`MemoriesPage.tsx:497,535`）；仓库无 DESIGN.md 作为视觉单一事实源。

**不必要文案**

- 内部术语裸露：deployment/revision/CAS 等；「接入信息/客户端接入/接入」三种命名并存。
- 误导性文案：搜索 20 条上限 × 客户端筛选导致计数与感知不符。

**易用性（面向非技术用户）**

- 简洁/专家双模式已存在，但简洁模式仍有缺口：action card 可跳到不在导航里的页面造成"迷路"；deployment/revision/CAS 等术语在简洁模式未隐藏；`setup.next_action="connect_client"` 后端有值前端没消费——CLI 配好模型的用户打开 UI 没有任何"创建第一个 chat token"的引导。
- 默认应让非技术用户在简洁模式下完成核心任务。简洁模式当前导航（`navigation.ts:52-55`）：开始=工作室，内容=记忆库+知识库，使用=模型与路由+报告与备份+接入信息。知识库已在，但记忆体检、用量统计仍只在专家模式，需纳入简洁模式。
- 约束：体检/用量进简洁模式不是只加导航入口——这两页原本面向专家，页面内的技术字段（如 revision/CAS、按 deployment 的拆分）需同步降级呈现，只留非技术用户关心的结果与结论；完整数据保留在专家模式或详情折叠/文档中。

已修复、不在范围内：复制 token 静默失败、401 无全局处理（8-12 后已修，抽查确认）。组件拆分、路由重构等工程改动不在范围内。

## 目标

1. 视觉收敛：双主题对比度达标、危险等级与确认弹窗策略一致、移动端死样式清理、颜色全部走 token。
2. 文案减负：删除/改写内部术语与误导性文案，命名全局统一，低风险操作不再反复确认。
3. 易用性优先：默认（简洁）模式让非技术用户不看技术细节即可完成核心任务（含知识库、记忆体检、用量统计）；技术细节收敛到专家模式与文档。

## 验收标准

1. 深/浅两主题正文与 muted 文字对比度均 ≥ WCAG AA（4.5:1），验证方式（脚本或工具）留记录。
2. 用户可见字符串中不再出现 deployment/revision/CAS/X-User-Id 等内部标识符；「客户端接入」类命名全 UI 唯一。
3. 确认弹窗仅用于 danger 级操作；编辑记忆等低风险保存直接生效，warning/danger 等级视觉样式一致。
4. 简洁模式下：导航包含知识库（已有）、记忆体检、用量统计三个核心功能入口；体检/用量两页在简洁模式下只呈现非技术用户关心的结果与结论（技术字段降级到专家模式或折叠/文档）；不出现内部术语；导航可达性与 action card 跳转目标一致（不出现"迷路"页）；`setup.next_action="connect_client"` 时给出"创建第一个 chat token"引导；核心任务路径（查看/搜索/编辑记忆、知识库、体检、用量、接入客户端）无需离开简洁模式。
5. 780px 以下无被覆盖的 sidebar 死样式；TSX 内联样式不引入 token 之外的色值。
6. `scripts/test.sh` 与 `cd services/memory-gateway/ui && npm run build` 通过；桌面与移动 Playwright e2e 不回归。

# Web Console 前端韧性：错误边界与失败可见性

## 背景

Memory Console（`services/memory-gateway/ui`）15 个页面均为大型组件，但全站没有任何 React 错误边界（无 `ErrorBoundary` / `componentDidCatch`）：任一页面渲染抛错即整站白屏，且刷新后 hash 路由仍指向出错页面，可能再次白屏，用户无法自救。

另有两处失败被静默处理：

- **未知 hash 无反馈**：`App.tsx` 的 `onHashChange` 中 `parseHash` 返回 `null` 时静默忽略，坏链接或手输地址后页面毫无反应。
- **角标失败被吞掉**：侧栏待办角标刷新 `refreshSignals` 对非 401 错误直接吞掉（注释「角标只是辅助信号」），角标可能长期过期而用户完全不知情。

## 目标

让 Console 出错时「可见、可恢复、可自助」：

1. **全局错误边界**：任一页面渲染异常不白屏，展示可操作的错误界面。
2. **未知地址可感知**：无效 hash 显示「页面不存在」并引导回工作室。
3. **角标失败可见**：角标数据拉取失败时展示失败状态并提供重试；401 仍保持强制回连接设置页的现有行为。

范围与边界：

- 仅改 `services/memory-gateway/ui` 前端，不动后端接口。
- 不改动现有 toast 与凭证感知错误文案体系（`utils/format.ts`）。
- 本期仅中文文案，不做 i18n；不引入新依赖（用 React 原生 class ErrorBoundary）。

## 验收标准

### 全局错误边界

- [ ] 人为让某页面组件抛错时整站不白屏，显示中文错误页，含错误摘要、「重试」和「返回工作室」按钮。
- [ ] 点击「返回工作室」或切换页面后无需整页刷新即可恢复正常导航。
- [ ] 错误边界同时覆盖页面渲染区和全局悬浮层（记忆档案抽屉、确认对话框）。
- [ ] 错误详情写入 console 便于诊断；提供「复制诊断信息」可选能力。

### 未知 hash 提示

- [ ] 访问未知 hash（如 `#/foo`）时显示「页面不存在」提示和返回工作室入口，不再静默停留。
- [ ] 现有合法 hash 行为不变：`#/memories/<id>`、`#/knowledge/<id>`、`#/<page>?memory=<id>` 及旧书签均可正常打开（回归）。

### 角标失败可见

- [ ] 角标刷新非 401 失败时，顶栏状态或角标区域出现可感知的失败提示，并提供重试入口。
- [ ] 连续失败不重复弹 toast 刷屏（节流或改为持久状态位）。
- [ ] 401 失败仍强制回连接设置页（现有行为回归通过）。

### 测试与验证

- [ ] 新增 Vitest 用例覆盖：错误边界渲染与恢复、未知 hash 提示、角标失败提示与节流。
- [ ] 新增/更新 Playwright e2e（桌面 + 移动 375/390）覆盖上述三条主路径。
- [ ] `cd services/memory-gateway/ui && npm run build` 通过；`scripts/test.sh` 无新增失败。
